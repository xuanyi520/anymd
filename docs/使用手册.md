## 一、这个工具解决什么问题

### 两个真实场景

**场景一：AI 读不懂二进制文件。**

你要让 Claude 帮你精读 50 篇 PDF。直接给它 `.pdf` 文件路径，它只能读到一堆二进制乱码。你得先把 PDF 变成纯文本。50 个文件，手动复制粘贴，一下午没了。

**场景二：AI 写的东西交付不了。**

Claude 给你写好了一份课程报告，是 Markdown 格式。但导师要 Word，答辩要 PPT，发给同学要 PDF。开三个软件来回倒腾，格式还老乱。

anymd 就是把这两件事固化成一条命令：

```
其他格式  ──[ to-md ]──→  Markdown  ──→  给 AI 读
Markdown  ──[ from-md ]──→  Word/PDF/PPT  ──→  给人交付
```

### 它不是自己写的转换器

| 方向 | 引擎 | 说明 |
|---|---|---|
| 学术 PDF → md | **pymupdf4llm 1.28** | 保留标题层级、表格、阅读顺序 |
| 其他格式 → md | **Microsoft markitdown 0.1.8** | 微软开源，覆盖 Office 全家桶 |
| md → 各种格式 | **pandoc 3.8** | 文档转换的老牌霸主 |
| md → 中文 PDF | pandoc + **Edge 无头打印** | 本机没有 LaTeX 时的替代路线 |
| md → xlsx | **openpyxl** | 从 md 里抽表格写进 Excel |

anymd 做的是把它们编排起来：选引擎、抽元数据、批量并发、处理路径冲突、加视觉模型、包一层 MCP 接口。

## 二、安装

### 2.1 环境要求

| 项目 | 要求 | 必需性 |
|---|---|---|
| Python | 3.10 及以上 | **必需** |
| pandoc | 3.x | **必需**（只做入向可以不装） |
| Microsoft Edge | 任意版本 | md → PDF 时必需 |
| Microsoft Word | 任意版本 | `.doc` 入向、`--pdf-engine word` 时必需 |
| 视觉模型密钥 | 火山方舟 / OpenAI 兼容 | 只有 `--vision` 需要 |

### 2.2 装 Python 依赖

```bash
git clone https://github.com/xuanyi520/anymd.git
cd anymd

python -m venv .venv
# Windows
.venv\Scripts\pip install -e .
# macOS / Linux
.venv/bin/pip install -e .
```

`-e` 是开发模式安装，改代码不用重装。

主要依赖会自动装好：`markitdown`、`pymupdf4llm`、`markdownify`、`mcp`。

> **注意**：`pymupdf4llm` 内部依赖 `pymupdf`，首次安装会编译或下载二进制包，需要几十秒到几分钟。

### 2.3 装 pandoc

**Windows**（任选其一）：

```powershell
winget install --id JohnMacFarlane.Pandoc
# 或者
choco install pandoc
```

也可以从 https://pandoc.org/installing.html 下 `.msi` 安装包。

**macOS**：

```bash
brew install pandoc
```

**Linux**：

```bash
sudo apt install pandoc      # Debian / Ubuntu
sudo dnf install pandoc      # Fedora
```

装完验证：

```bash
pandoc --version
```

### 2.4 Windows 免激活启动器

项目根目录有 `anymd.cmd`，它直接调用 `.venv` 里的可执行文件，**不需要先激活虚拟环境**：

```bat
E:\Dowmload\anymd\anymd.cmd to-md 论文.pdf
```

想在任何目录直接敲 `anymd`，把这个目录加进系统 PATH：

1. `Win + R` → 输入 `sysdm.cpl` → 回车
2. 「高级」→「环境变量」→ 用户变量里的 `Path` →「编辑」
3. 「新建」，填入项目根目录（例如 `E:\Dowmload\anymd`）
4. 确定，重开终端

之后：

```powershell
anymd to-md 论文.pdf
```

### 2.5 验证安装

```bash
anymd formats
```

正常输出会列出全部入向和出向格式。如果报 `command not found`，说明 PATH 没配好，用完整路径：

```bat
E:\Dowmload\anymd\anymd.cmd formats
```

再验证一次实际转换能力：

```bash
anymd from-md README.md --to html
```

生成 `README.html` 就说明 pandoc 正常。

## 三、三种用法

### 3.1 用法一：拖文件（最省事）

把文件或文件夹**直接拖到 `anymd.cmd` 的图标上**，会弹出交互菜单。

| 拖进去的东西 | 菜单给什么选项 |
|---|---|
| **Markdown 文件** | 转成 Word / PDF / PPT / HTML / EPUB / Excel / 纯文本 / 其他格式 |
| **其他格式文件** | 转成 Markdown（可加元数据、抽图片）；或先转 md 再转别的格式 |
| **文件夹** | 批量转换，可选递归子目录、加元数据、指定输出目录 |
| **多个文件** | 逐个选择，或统一处理 |
| **网页 URL** | 抓取正文存成 Markdown |

转换完成后菜单里可以直接「打开输出文件夹」。

### 3.2 用法二：交互窗口

`Win + R` → 输入 `powershell` → 回车 → 敲 `anymd`（不带任何参数）→ 回车。

进入交互模式后：

- 把文件或文件夹**直接拖进窗口**
- 输入路径时，含空格的文件名用引号包住
- 支持一次拖入多个
- 输入 `0` 跳过当前文件、返回主菜单
- 输入 `q` 退出

> 只要第一个参数不是已知子命令，都会进交互模式。所以 `anymd 论文.pdf` 也会弹交互菜单，而不是报错。

### 3.3 用法三：命令行

适合写脚本、放进自动化流程。全部子命令见下面几章。

```bash
anymd to-md   论文.pdf
anymd from-md 报告.md --to docx
anymd batch   D:\文献 --to md
```

### 3.4 中文命令别名

中英文命令完全等价，记不住英文就用中文：

| 中文 | 英文 | 作用 |
|---|---|---|
| `anymd 转md` | `to-md` | 任意格式 → Markdown |
| `anymd 转出` | `from-md` | Markdown → 其他格式 |
| `anymd 批量` | `batch` | 批量转换目录 |
| `anymd 格式` | `formats` | 列出支持的格式 |
| `anymd 视觉测试` | `vision-test` | 测试视觉模型是否可用 |
| `anymd 服务` | `mcp` | 启动 MCP server |
| `anymd 帮助` | `--help` | 显示帮助 |

## 四、入向：任意格式 → Markdown

### 4.1 基本用法

```bash
anymd to-md 论文.pdf
```

不指定输出时，结果写到**默认输出目录**（见[第九章](#九输出路径规则)）。

一次转多个：

```bash
anymd to-md 文件1.pdf 文件2.docx 文件3.xlsx
```

多文件 + `-o` 时，`-o` **必须是一个已存在的目录**，否则报错：

```
多个输入时 -o 必须是已存在的目录
```

### 4.2 全部参数

| 参数 | 默认 | 作用 |
|---|---|---|
| `inputs` | — | 文件路径或 URL，可写多个 |
| `-o, --output` | 默认输出目录 | 输出文件或目录 |
| `--engine` | `auto` | 入向引擎：`auto` / `markitdown` / `pymupdf` / `pymupdf4llm` |
| `--frontmatter` | 关 | 在正文前加 YAML 元数据头 |
| `--extract-images` | 关 | 把 PDF 里的图片抽到 `assets/<文件名>/` |
| `--join-lines` | 关 | 尝试把被硬换行切断的段落接回去 |
| `--vision` | 关 | 启用视觉模型 |
| `--vision-mode` | `auto` | 视觉模式：`auto` / `describe` / `ocr` / `chart` / `formula` |
| `--vision-model` | 配置文件里的值 | 临时覆盖视觉模型名 |
| `--vision-max-pages` | `50` | 扫描版 PDF 最多识别多少页 |
| `--json` | 关 | 结果以 JSON 输出，方便脚本解析 |
| `--no-overwrite` | 关 | 输出已存在时跳过，不覆盖 |

### 4.3 加元数据

```bash
anymd to-md 论文.pdf --frontmatter
```

会在正文最前面生成：

```yaml
---
title: "论文标题（自动取自第一个一级标题）"
source: "E:/Paper/论文.pdf"
type: "pdf"
engine: "pymupdf4llm"
converted_at: "2026-10-31T15:20:33+08:00"
pages: 12
---
```

**为什么有用**：做知识库或 RAG 时，这些字段能让你按来源、类型、时间检索，而不是把所有文件混成一片。Obsidian、Logseq 也认这个格式。

> 路径里的反斜杠会被自动转成正斜杠——YAML 里反斜杠是转义符，`E:\Paper` 会被解析成非法转义。

### 4.4 抽图片

```bash
anymd to-md 论文.pdf --extract-images
```

图片抽到**输出 md 同目录下的** `assets/<源文件名>/`：

```
论文.md
assets/
└── 论文/
    ├── image_001.png
    └── image_002.png
```

### 4.5 修复断行

中文 PDF 转出来的 md 经常长这样：

```
本研究的主要目的是建立一套适用于基层医院的
肝癌早期筛查流程。
```

一句话被中间劈开了。加 `--join-lines`：

```bash
anymd to-md 论文.pdf --join-lines
```

> **默认关闭**。因为它判断"这行是不是没写完"靠的是启发式规则，遇到代码块、表格、列表时会误伤。学术论文可以开，技术文档建议不开。

### 4.6 换引擎

PDF 默认走 pymupdf4llm。如果转出来效果不好（比如版面复杂导致顺序乱），换 markitdown 试试：

```bash
anymd to-md 论文.pdf --engine markitdown
```

| 引擎 | 适合 |
|---|---|
| `pymupdf4llm` | 文字版学术论文，保留标题层级和表格 |
| `markitdown` | 版面简单的 PDF、以及在 pymupdf 抽不出字时的兜底 |

`--engine auto` 的实际行为：PDF 走 pymupdf4llm，抽出的正文少于 20 个非空白字符时自动回退 markitdown；其他格式一律 markitdown。

### 4.7 支持的入向格式

| 类型 | 扩展名 | 引擎 | 备注 |
|---|---|---|---|
| PDF | `.pdf` | pymupdf4llm（回退 markitdown） | 扫描版需要 `--vision` |
| Word | `.docx` | markitdown | 直接支持 |
| Word 旧版 | `.doc` | markitdown + 本机 Word | 依赖本机装了 Word |
| PowerPoint | `.pptx` | markitdown | 按幻灯片顺序 |
| Excel | `.xlsx` `.xls` | markitdown | 每个 sheet 一张表 |
| 网页 | `.html` `.htm` | markitdown | 去导航和样式 |
| 电子书 | `.epub` | markitdown | |
| 结构化文本 | `.csv` `.json` `.xml` | markitdown | 保留结构 |
| 纯文本 | `.txt` `.yaml` `.toml` `.py` 等 | 直接读取 | |
| 图片 | `.jpg` `.png` `.gif` `.bmp` `.webp` `.tif` | markitdown / 视觉模型 | 不加 `--vision` 只能读到元数据 |
| URL | `http://` `https://` | markitdown | 直接抓正文 |

## 五、出向：Markdown → 其他格式

### 5.1 基本用法

```bash
anymd from-md 报告.md --to docx
```

`--to` 是**必填**的。不填会直接报错。

不指定 `-o` 时，输出放在**源文件同目录、同主名**：

```
报告.md  →  报告.docx
```

### 5.2 全部参数

| 参数 | 默认 | 作用 |
|---|---|---|
| `inputs` | — | Markdown 文件（也接受 `.txt`） |
| `--to` | **必填** | 目标格式，见[附录 B](#附录-b格式别名表) |
| `-o, --output` | 源文件同目录 | 输出文件或目录 |
| `--toc` | 关 | 生成目录 |
| `--reference-doc` | 无 | docx / pptx 的模板文件 |
| `--pdf-engine` | `auto` | PDF 生成方式：`auto` / `edge` / `word` |
| `--json` | 关 | JSON 输出 |
| `--no-overwrite` | 关 | 已存在则跳过 |

### 5.3 各目标格式的具体情况

| 目标 | 实现 | 注意点 |
|---|---|---|
| `docx` | pandoc | 支持 `--reference-doc` 控制字体版式 |
| `pdf` | Edge 无头打印 / Word | 中文正常，见 5.4 |
| `pptx` | pandoc | **按标题分页**，一个一级/二级标题一页，版式朴素 |
| `xlsx` | openpyxl | **只搬表格**，正文文字不进 Excel，见 5.5 |
| `html` | pandoc（html5） | 单文件，内联样式 |
| `epub` | pandoc（epub3） | 电子书格式 |
| `latex`/`tex` | pandoc | 输出 `.tex` 源码 |
| `rst` `odt` `rtf` `org` `txt` `json` `mediawiki` `asciidoc` | pandoc | 直接转 |
| `md` | 直接复制 | 相当于改名 |

**不支持**：`png` / `jpg` 图片输出，会明确报错「图片输出暂未开放；可先转 PDF，再截图」。

### 5.4 PDF 的两种生成方式

```bash
anymd from-md 报告.md --to pdf                 # 自动选
anymd from-md 报告.md --to pdf --pdf-engine edge
anymd from-md 报告.md --to pdf --pdf-engine word
```

| 引擎 | 原理 | 优点 | 缺点 |
|---|---|---|---|
| `edge`（默认） | pandoc → HTML → Edge 无头打印 | 中文开箱即用，不依赖 Office | 样式由内置 CSS 控制，改动需改代码 |
| `word` | pandoc → docx → Word 另存 PDF | 可用 Word 的完整排版能力 | 必须装 Word，速度慢 |

`auto` 在有 Edge 时用 Edge，找不到 Edge 才退到 Word。

**Edge 路线的排版**由 `anymd/core.py` 里的 `PRINT_CSS` 控制：A4 纸、22mm/18mm 页边距、11.5pt 正文、宋体/思源宋体、微软雅黑标题、表格斑马纹。想改字号或字体，直接改那段 CSS。

### 5.5 md → xlsx 的特殊行为

Excel 是表格容器，而 Markdown 是文档。所以这个转换**只搬 Markdown 里的表格，正文文字会丢掉**。

```markdown
# 实验数据

共三组样本（这句话不会进 Excel）。

| 组别 | 样本数 | 准确率 |
|---|---|---|
| A | 100 | 0.92 |
| B | 120 | 0.89 |
```

转成 xlsx 后只有一个 sheet，内容是那张表。**如果想让文字也保留，应该转 docx 或 pdf。**

### 5.6 用模板控制版式

程序生成的 docx 字体往往不符合学院要求。给一个模板文件，pandoc 会套用它里面定义好的样式：

```bash
anymd from-md 报告.md --to docx --reference-doc 学院模板.docx
anymd from-md 讲稿.md --to pptx --reference-doc 组会模板.pptx
```

**模板怎么做**：先手动做一份符合要求的空白文档，把标题 1/2/3、正文、表格、代码的样式都调好，存下来。**模板里不用写内容**，pandoc 只读样式。

### 5.7 加目录

```bash
anymd from-md 长报告.md --to pdf --toc
```

pandoc 会根据标题层级自动抽目录。需要文档里有标题（`#`、`##`）才有内容。

## 六、批量转换

### 6.1 基本用法

```bash
anymd batch D:\文献 --to md
```

`--to md` 表示**入向**（各种格式 → md）；其他值表示**出向**（md → 该格式）。

反向：

```bash
anymd batch D:\文献_md --to docx
```

### 6.2 全部参数

| 参数 | 默认 | 作用 |
|---|---|---|
| `input_dir` | — | 输入目录（必须是目录） |
| `--to` | `md` | 目标格式 |
| `--outdir` | 见 6.3 | 输出目录 |
| `--no-recursive` | 关 | 不递归子目录 |
| `--engine` | `auto` | 入向引擎 |
| `--workers` | `4` | 并发线程数 |
| `--frontmatter` | 关 | 加 YAML 元数据 |
| `--extract-images` | 关 | 抽图片 |
| `--join-lines` | 关 | 修复断行 |
| `--vision` | 关 | 启用视觉模型（批量时开销大，见第七章） |
| `--vision-mode` | `auto` | 视觉模式 |
| `--vision-model` | 配置文件 | 覆盖模型 |
| `--vision-max-pages` | `50` | 单文件最多识别页数 |
| `--json` | 关 | 输出完整 JSON 结果 |
| `--no-overwrite` | 关 | 已存在则跳过 |

### 6.3 输出目录默认值

| 方向 | 默认输出目录 |
|---|---|
| 入向（`--to md`） | `md输出\<源文件夹名>\` |
| 出向（其他 `--to`） | `<源文件夹的上级>\<源文件夹名>_converted\` |

想指定就用 `--outdir`：

```bash
anymd batch D:\文献 --to md --outdir D:\文献_md
```

### 6.4 目录结构会被保留

输入：

```
D:\文献\
├── 2023\
│   ├── a.pdf
│   └── b.docx
└── 2024\
    └── c.pdf
```

输出（`--to md`）：

```
md输出\文献\
├── 2023\
│   ├── a.md
│   └── b.md
├── 2024\
│   └── c.md
└── manifest.json
```

### 6.5 会跳过什么

批量转换自动忽略三类文件，避免无限递归和垃圾输出：

1. **名字以 `.` 开头的目录和文件**（`.git`、`.venv`、`.venv` 里的东西全跳过）
2. **输出目录自身**（`--outdir` 指向的目录，防止把上次的结果再转一遍）
3. **方向不对的文件**：
   - `--to md` 时只处理**非 md** 文件（不会把已有的 md 再转一遍）
   - `--to docx` 等出向时只处理 **md** 文件（不会把 `manifest.json` 塞给 pandoc）

### 6.6 manifest.json

每次批量转换都会在输出目录里生成 `manifest.json`：

```json
{
  "input_dir": "D:\\文献",
  "output_dir": "D:\\文献_md",
  "mode": "to-md",
  "total": 128,
  "succeeded": 125,
  "failed": 3,
  "generated_at": "2026-10-31T15:20:33+08:00",
  "items": [
    {
      "source": "D:\\文献\\2023\\a.pdf",
      "output": "D:\\文献_md\\2023\\a.md",
      "format": "md",
      "ok": true,
      "chars": 24188,
      "pages": 12,
      "engine": "pymupdf4llm",
      "elapsed": 1.83,
      "warnings": [],
      "error": null
    }
  ]
}
```

**每个文件的引擎、耗时、字符数、页数、失败原因都在里面**。125 个成功 3 个失败时，不用翻屏幕，直接看 `items` 里 `ok: false` 的那三条。

### 6.7 并发数怎么调

默认 4 线程。PDF 转 md 是 CPU 密集操作：

- **SSD + 8 核以上**：`--workers 8` 能快一倍
- **机械硬盘**：别超过 4，I/O 会先饱和，反而更慢
- **开了 `--vision`**：别超过 2，瓶颈在网络和 API 限流

```bash
anymd batch D:\文献 --to md --workers 8
```

## 七、视觉模型

### 7.1 它解决什么

Markdown 转换引擎只能读**文字**。以下三种东西它读不懂：

| 情况 | 不加 `--vision` | 加 `--vision` |
|---|---|---|
| 扫描版 PDF（图片扫描） | 转出空白或几个乱码 | 逐页渲染，识别出完整文字 |
| 图片文件（jpg/png） | 只能读到元数据 | 生成内容描述 |
| 论文里的图表 / 公式 | 图片位置留空 | 图表还原成 Markdown 表格，公式转 LaTeX |

### 7.2 配置密钥

anymd 的密钥查找优先级：

```
环境变量 VISION_API_KEY
    ↓ 没找到
anymd 目录下的 .env 文件
    ↓ 没找到
~/.claude/skills/ppt-master/.env 里的 ARK_API_KEY
```

三个都可以。最省事的做法是复制示例文件：

```bash
cp .env.example .env
```

然后编辑 `.env`：

```ini
VISION_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
VISION_MODEL=doubao-seed-2-1-lite-260915
VISION_API_KEY=你的密钥
```

> `.env` 已在 `.gitignore` 里，不会被提交。**千万别把密钥写进代码或 README。**

### 7.3 火山方舟第一次使用要开通模型

只填密钥是不够的，模型得先在控制台开通：

1. 打开 https://console.volcengine.com/ark
2. 左侧「模型广场」
3. 搜索 `doubao-seed-2-1-lite`（便宜）或 `doubao-seed-2-1-pro`（质量好）
4. 点「**开通服务**」

没开通时调用会返回类似「模型未开通」的错误。

验证：

```bash
anymd vision-test
```

看到 `[成功] 视觉模型可用。` 就配好了。

用真实图片测试：

```bash
anymd vision-test --image D:\某张图.png --mode describe
```

### 7.4 换用其他视觉模型

任何 OpenAI 兼容接口都能接。改 `.env` 里的两个字段即可：

**OpenAI**

```ini
VISION_BASE_URL=https://api.openai.com/v1
VISION_MODEL=gpt-4o
VISION_API_KEY=sk-...
```

**通义千问（阿里云百炼）**

```ini
VISION_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
VISION_MODEL=qwen-vl-max
```

**智谱**

```ini
VISION_BASE_URL=https://open.bigmodel.cn/api/paas/v4
VISION_MODEL=glm-4v-plus
```

### 7.5 五种识别模式

| 模式 | 做什么 | 适合 |
|---|---|---|
| `auto`（默认） | 自动判断是图表、公式、文档还是照片 | 不知道内容时用它 |
| `describe` | 只做客观描述 | 照片、示意图 |
| `ocr` | 只提取文字，保持段落结构 | 扫描件、截图 |
| `chart` | 还原成 Markdown 表格 | 柱状图、折线图、流程图 |
| `formula` | 转成 LaTeX | 数学公式 |

```bash
anymd to-md 扫描件.pdf --vision --vision-mode ocr
anymd to-md 论文.pdf --vision --vision-mode chart
anymd to-md 公式截图.png --vision --vision-mode formula
```

### 7.6 什么时候会自动触发

**扫描版 PDF 的检测逻辑**：pymupdf4llm 转完后统计非空白字符数，若少于 `max(30, 页数 × 20)`，判定为扫描版，自动改走逐页视觉识别。

举例：一份 10 页的扫描 PDF，正常应该有几千字。如果只抽出 80 个字符（80 < 200），就会触发。

**内嵌图片**：`--vision` + `.pdf` / `.pptx` / `.docx` 时，会把文档里的图片抽出来逐张描述，追加一个「图片描述」章节。

### 7.7 费用与限制

| 项目 | 值 | 说明 |
|---|---|---|
| 图片压缩 | 最长边压到 **1800px** | 控制 token 消耗 |
| 内嵌图片上限 | **30 张** | 超出部分不处理 |
| 扫描 PDF 页数上限 | **50 页**（`--vision-max-pages`） | 大文件分批处理 |
| 计费单位 | 按图片 / 按页 | 一份 200 页扫描件 = 200 次调用 |

**大批量处理扫描件前先算账**：200 页 × 单页费用。可以先加 `--vision-max-pages 10` 试十页，看看效果和费用再决定。

## 八、MCP：在 Claude Code 里直接调用

### 8.1 是什么

MCP（Model Context Protocol）让 Claude Code 能直接调用这个工具。配好之后不用敲命令，直接说话：

> 「把 D:\Paper\那篇.pdf 转成 markdown，加上元数据」
>
> 「把这个 md 生成一份 Word 和一份 PDF」
>
> 「把 D:\资料 整个目录批量转成 markdown，输出到 D:\资料_md」

### 8.2 注册

```bash
claude mcp add -s user anymd -e PYTHONUTF8=1 -- "E:\Dowmload\anymd\.venv\Scripts\python.exe" -m anymd mcp
```

参数含义：

| 部分 | 作用 |
|---|---|
| `-s user` | 注册到用户级，所有项目都能用 |
| `-e PYTHONUTF8=1` | 强制 UTF-8，避免中文路径乱码 |
| `python.exe` | **必须写绝对路径** |
| `-m anymd mcp` | 以 stdio 方式启动 MCP server |

> **python 路径一定要写绝对路径。** 如果只写 `python`，可能解析到别的虚拟环境，缺依赖导致连不上。

### 8.3 四个工具

#### `to_markdown`

把任意格式转成 Markdown 文本。

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `path` | str | 必填 | 本地绝对路径或 http(s) URL |
| `output` | str | None | 填写则写入文件并返回摘要；不填直接返回 Markdown 正文 |
| `engine` | str | `auto` | `auto` / `markitdown` / `pymupdf` |
| `frontmatter` | bool | false | 加 YAML 元数据 |
| `extract_images` | bool | false | 抽图片（仅 `output` 模式生效） |
| `max_chars` | int | 0 | 返回正文最大字符数，0 = 不截断 |
| `vision` | bool | false | 启用视觉模型 |
| `vision_mode` | str | `auto` | 视觉模式 |
| `vision_model` | str | None | 覆盖模型 |

**`max_chars` 很实用**：一本 300 页的书可能有 50 万字，全塞进上下文会爆。设 `max_chars=20000` 先读开头，需要细节再单独转换。

#### `from_markdown`

Markdown → 其他格式。

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `path` | str | 必填 | Markdown 文件路径 |
| `to` | str | 必填 | 目标格式 |
| `output` | str | None | 不填则同目录同主名 |
| `toc` | bool | false | 生成目录 |
| `reference_doc` | str | None | docx/pptx 模板 |

#### `batch_convert`

批量转换目录。

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `input_dir` | str | 必填 | 输入目录 |
| `to` | str | `md` | 目标格式 |
| `outdir` | str | None | 不填则 `<输入目录名>_converted` |
| `recursive` | bool | true | 是否递归 |
| `workers` | int | 4 | 并发数 |
| `frontmatter` | bool | false | 加元数据 |

返回摘要（总数、成功数、失败数、前 20 条失败原因），**不返回每个文件的全文**——否则 128 个文件的结果会直接撑爆上下文。

#### `list_formats`

列出支持的格式，无参数。

### 8.4 连不上怎么办

**症状：Claude Code 里看不到 anymd 的工具，或提示 `CONNECTION_CLOSED`。**

按顺序排查：

1. **python 路径对不对**
   ```bash
   "E:\Dowmload\anymd\.venv\Scripts\python.exe" -m anymd mcp
   ```
   在普通终端里跑这条，如果立刻报 `ModuleNotFoundError`，说明路径指错了环境。

2. **stdout 有没有被污染**
   MCP 走 stdio 协议，**stdout 里不能有任何多余输出**。任何一句 `print()` 调试代码都会让协议解析失败。调试信息一律写 `sys.stderr`。

3. **mcp 包版本**
   本项目要求 `mcp >= 2.0`。SDK 2.x 里必须用 `MCPServer`，旧教程里的 `FastMCP` 已经不能用了。

4. **重新注册**
   ```bash
   claude mcp remove -s user anymd
   claude mcp add -s user anymd -e PYTHONUTF8=1 -- "绝对路径\python.exe" -m anymd mcp
   ```

5. **在 Claude Code 里查状态**
   ```
   /mcp
   ```

## 九、输出路径规则

这一章值得单独看，因为路径是最容易搞混的地方。

### 9.1 to-md 的输出

| 情况 | 输出位置 |
|---|---|
| 不给 `-o` | 默认输出目录 `<文件名>.md` |
| `-o` 是已存在的目录 | `<目录>/<文件名>.md` |
| `-o` 以 `/` 或 `\` 结尾 | 自动建目录，写 `<目录>/<文件名>.md` |
| `-o` 是文件路径但不是 `.md` 后缀 | 自动改成 `.md` |
| `-o` 和源文件相同 | 改成 `<文件名>.converted.md` |
| 多文件 + `-o` | `-o` 必须是已存在目录，否则报错 |

**默认输出目录**是：

```
环境变量 ANYMD_OUTPUT_DIR 指定的路径
    ↓ 没设
<anymd 项目根目录>/md输出/
```

### 9.2 from-md 的输出

| 情况 | 输出位置 |
|---|---|
| 不给 `-o` | 源文件同目录、同主名、新扩展名 |
| `-o` 是已存在的目录 | `<目录>/<文件名>.<目标扩展名>` |
| `-o` 以 `/` 或 `\` 结尾 | `<目录>/<文件名>.<目标扩展名>` |
| `-o` 没有扩展名 | 自动补上目标扩展名 |
| `-o` 和源文件相同 | 报错「输出路径不能与源文件相同」 |

### 9.3 batch 的输出

见 [6.3](#63-输出目录默认值)。目录结构按相对路径保留。

### 9.4 重名怎么办

| 场景 | 行为 |
|---|---|
| to-md 不指定 `-o`，默认目录里已有同名 | **自动加 `_1`、`_2`**，不覆盖 |
| to-md 指定了 `-o`，文件已存在 | **默认覆盖**（加 `--no-overwrite` 则跳过并记为失败） |
| from-md 输出已存在 | **默认覆盖**（加 `--no-overwrite` 则报错） |
| 交互模式 | 弹菜单让你选「覆盖 / 自动改名 / 取消」 |

### 9.5 抽出来的图片放哪

只有 `--extract-images` 或 `--vision` 才会抽图，位置是：

```
<输出 md 的所在目录>/assets/<源文件名>/
```

例如 `anymd to-md D:\Paper\论文.pdf -o D:\out\论文.md --extract-images`：

```
D:\out\
├── 论文.md
└── assets\
    └── 论文\
        ├── image_001.png
        └── image_002.png
```

## 十一、故障排查

### 11.1 中文显示成乱码

**症状**：终端里输出 `[鎴愬姛]` 这种乱码，或者转换出的 md 是乱码。

**原因**：中文 Windows 的 CMD / PowerShell 5.1 默认用 GBK，而 Python 输出是 UTF-8。

**处理**：

```powershell
# 临时
chcp 65001
$OutputEncoding = [Console]::OutputEncoding = [Text.Encoding]::UTF8
```

或者用 `PYTHONUTF8=1` 启动：

```bash
PYTHONUTF8=1 anymd formats
```

anymd 本身做了自适应：Git Bash 走 UTF-8，PowerShell/CMD 走 GBK。如果还乱，是终端字体或代码页的问题。

### 11.2 `pandoc: command not found`

```bash
pandoc --version
```

没有就装（见 [2.3](#23-装-pandoc)）。装完**必须重开终端**，PATH 才会生效。

如果装了但还是找不到，检查是不是装在用户目录而 PATH 只加了系统目录。

### 11.3 md → PDF 失败

**症状**：`Edge` 相关报错，或者输出 0 字节。

**排查**：

1. 确认 Edge 路径存在：
   ```
   C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe
   ```
2. 换 Word 引擎试：
   ```bash
   anymd from-md 报告.md --to pdf --pdf-engine word
   ```
3. 先转 HTML 看看内容是否正确：
   ```bash
   anymd from-md 报告.md --to html
   ```
   如果 HTML 都不对，问题在 pandoc 阶段，不在打印阶段。

### 11.4 `.doc` 转换失败

`.doc` 是二进制旧格式，必须借本机 Word 打开另存为 `.docx`。没装 Word 就转不了。

**处理**：手动用 WPS 或 Word 打开，另存为 `.docx`，再转。

### 11.5 扫描版 PDF 转出来是空的

**症状**：输出 md 只有几行，`[警告] PDF 疑似扫描版`。

**处理**：

```bash
anymd to-md 扫描件.pdf --vision --vision-mode ocr
```

前提是视觉模型已配好（先跑 `anymd vision-test`）。

### 11.6 图片转出来只有文件名

不加 `--vision` 时，图片只能读到 EXIF 元数据，内容是空的（会提示「图片未识别出文字」）。

```bash
anymd to-md 截图.png --vision
```

### 11.7 PDF 里公式变成乱码源码

`$E=mc^2$` 变成 `\sqrt{x^2+y^2}` 这种源码。

**原因**：PDF 里公式本来就是以图片或特殊字体嵌入的，文字提取拿到的是字体编码。

**处理**：

```bash
anymd to-md 论文.pdf --vision --vision-mode formula
```

或者接受它——Markdown 里的 LaTeX 源码本身是合法的，喂给 AI 完全能理解。

### 11.8 表格转出来是散的

复杂表格（跨行、跨列、嵌套）在任何 PDF → md 引擎里都会崩。这不是 bug，是 PDF 格式本身的限制——PDF 里根本没有"表格"这个概念，只有一堆带坐标的文字。

**处理**：接受损失，或者用视觉模型：

```bash
anymd to-md 论文.pdf --vision --vision-mode chart
```

### 11.9 `ModuleNotFoundError`

**症状**：`No module named 'anymd'` 或 `No module named 'markitdown'`。

**原因**：`python` 解析到了别的环境。

**处理**：用绝对路径

```bash
E:\Dowmload\anymd\.venv\Scripts\python.exe -m anymd formats
```

或者确认虚拟环境激活了：

```bash
.venv\Scripts\activate
python -m anymd formats
```

### 11.10 批量转换很慢

- PDF 转 md 是 CPU 密集的，正常 1-3 秒一份
- 提高并发：`--workers 8`
- 开了 `--vision` 会慢十倍以上，因为每页都要等 API 返回
- 机械硬盘别调高并发

### 11.11 输出目录里堆满了旧文件

`--no-overwrite` 可以让已存在的输出跳过：

```bash
anymd batch D:\文献 --to md --no-overwrite
```

但注意：跳过也算「失败」，会记在 `manifest.json` 里。

## 十二、Python API

除了命令行，也可以直接 import 用：

```python
from anymd.core import to_markdown, from_markdown, batch_convert

# 转成 Markdown
res = to_markdown("论文.pdf", "论文.md", frontmatter=True)
print(res.ok, res.chars, res.engine, res.error)

# 转成 Word
res = from_markdown("报告.md", "docx", "报告.docx", toc=True)
print(res.ok, res.output, res.elapsed)

# 批量
results = batch_convert("D:\\文献", to="md", workers=8)
ok = sum(1 for r in results if r.ok)
print(f"{ok}/{len(results)} 成功")
```

`ConvertResult` 的字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `source` | str | 源路径 |
| `output` | str | 输出路径 |
| `format` | str | 目标格式 |
| `ok` | bool | 是否成功 |
| `chars` | int | md 是字符数，其他是字节数 |
| `pages` | int / None | 页数（仅 PDF） |
| `engine` | str | 实际用的引擎 |
| `elapsed` | float | 耗时（秒） |
| `warnings` | list | 警告信息 |
| `error` | str / None | 失败原因 |

只想拿文本不落盘，用 `render_markdown`：

```python
from anymd.core import render_markdown

rendered = render_markdown("论文.pdf", vision=True)
print(rendered.text)      # Markdown 正文
print(rendered.engine)    # 用了哪个引擎
```

## 十三、FAQ

**Q：能不能转成图片（png/jpg）？**

不能，会明确报错。需要的话先转 PDF，再截图或导出图片。

**Q：md → pptx 为什么这么丑？**

pandoc 生成 pptx 的逻辑是「按标题分页」，它没有任何版式设计能力。想要好看的 PPT，用专门的 PPT 工具链（比如 ppt-master），anymd 的定位是把文字搬过去。

**Q：能不能保留原文档的所有格式？**

不能。任意格式 → Markdown → 任意格式，中间必然有信息损失。Markdown 只表达**结构**（标题、段落、列表、表格、代码、强调），不表达字号、颜色、分栏、浮动位置。

要保真就别走这条路——直接用原格式编辑。

**Q：为什么不直接 PDF → Word？**

理论上可以（pandoc 不支持，别的工具可以），但质量更差。走 PDF → md → Word 至少能保证结构是对的，只是样式要重排。

**Q：转换会不会覆盖我的原文件？**

不会。输出路径永远是新的：to-md 默认写到 `md输出/`，from-md 默认写同目录不同扩展名。并且有防护——输出路径等于源路径时会自动改名或报错。

**Q：能不能监控文件夹自动转换？**

还没有。这是计划中的功能。

**Q：能不能并行处理多个大 PDF？**

用 `batch` 命令，配 `--workers`。单文件转换是串行的。

**Q：`.md` 文件用 to-md 转会怎样？**

直接复制，引擎标为 `copy`。

**Q：Windows 路径里的反斜杠要转义吗？**

bash 里反斜杠是转义符，用正斜杠更省事：

```bash
anymd to-md D:/Paper/论文.pdf          # 推荐
```

## 附录 A：完整参数速查

```
anymd to-md <inputs...> [选项]
  -o, --output PATH          输出文件或目录
  --engine {auto,markitdown,pymupdf,pymupdf4llm}
  --frontmatter              加 YAML 元数据
  --extract-images           抽图片到 assets/
  --join-lines               修复被硬换行切断的段落
  --vision                   启用视觉模型
  --vision-mode {auto,describe,ocr,chart,formula}
  --vision-model NAME        覆盖视觉模型
  --vision-max-pages N       扫描 PDF 最多识别页数（默认 50）
  --json                     JSON 输出
  --no-overwrite             已存在则跳过

anymd from-md <inputs...> --to FORMAT [选项]
  --to FORMAT                目标格式（必填）
  -o, --output PATH          输出文件或目录
  --toc                      生成目录
  --reference-doc PATH       docx/pptx 模板
  --pdf-engine {auto,edge,word}
  --json
  --no-overwrite

anymd batch <input_dir> [选项]
  --to FORMAT                默认 md
  --outdir PATH              输出目录
  --no-recursive             不递归
  --engine {auto,markitdown,pymupdf,pymupdf4llm}
  --workers N                并发数（默认 4）
  --frontmatter
  --extract-images
  --join-lines
  --vision
  --vision-mode {...}
  --vision-model NAME
  --vision-max-pages N
  --json
  --no-overwrite

anymd formats                列出支持的格式
anymd vision-test [--image PATH] [--mode MODE] [--model NAME]
anymd mcp                    启动 MCP server（stdio）
```

**退出码**：`0` 全部成功，`1` 有失败，`2` 参数用法错误。
